# Foundation plan

The product provides portable skills, repeatable installation, and approved
project conventions. It starts with software development in Claude Code.

| Stage | Acceptance |
| --- | --- |
| Foundation | Locked environment, portable CLI, contribution and security guides, CI and secret scanning |
| Pilot | Install bootstrap, planning, and review in a disposable Git project, invoke all three in Claude Code, and confirm private conventions persist |
| Lifecycle | Verify idempotence, conflicts, interruption recovery, rollback and preservation of unrelated files |
| P0 | Add Git branch, commit, pull request, and grilling workflows with explicit invocation |
| Close | Execute the platform CI matrix and confirm the Claude Code pilot before declaring support |

The CLI and P0 skill definitions are in the repository. The Windows pilot
verified installation, convention readback, and discovery of the three pilot
skills in Claude Code 2.1.332. Verify runtime version support and package name
availability before publishing.

## Foundation audit

| Severity | Evidence and impact | Change and verification |
| --- | --- | --- |
| P0 | Discovery printed raw branch and command evidence. Configuration validation could echo a private input. | Default output is a summary, detailed evidence is explicit, and configuration diagnostics omit values. Regression tests use synthetic markers. |
| P0 | The installation journal was loaded without checking its structure or snapshot content hashes. Damage could trigger an error or allow inconsistent file operations. | Validate the complete manifest before mutation. Regression tests cover invalid JSON, schema errors, duplicate keys, and hash mismatches. |
| P1 | A different command could implicitly resume an interrupted mutation, while retrying an update still depended on its original source. | Report the pending command and resume it from the journal. A regression test interrupts the second file write and completes the original update without its source. |
| P1 | Storage and discovery relied on broad path and file checks, and new POSIX directories inherited default modes. | Reject managed links and non-regular files, check directories before traversal, and use owner-only modes for new private directories. The Windows junction regression passed outside the restricted test sandbox. |
| P2 | Pilot skills requested multiple conventions and discovery evidence without first establishing a need. | Read only task-relevant fields. Discovery summary and explicit skill invocation reduce context loading by design. Token usage has not been measured. |

The audit verified the Windows CLI lifecycle in a synthetic checkout with
spaces, and Claude Code 2.1.332 discovered the three pilot skills from a nested
directory. The isolated Claude profile required sign-in for invocation.
The published baseline passed hosted CI. Run the hosted matrix again for
these changes before claiming platform validation. Use synthetic projects for
the authenticated pilot. The existing Git and grilling skill definitions
remain outside the audited pilot workflows.

Future stages cover contextual retrieval and handoffs, orchestrated agents,
distributed work, externally enforced corporate isolation, an executive
assistant, evaluation-driven optimization, and new workflow domains.
